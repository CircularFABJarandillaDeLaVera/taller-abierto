# Plan de trabajo

Estimación provisional, no compromiso de plazo: fase 0, 0,5–1 jornada; fase 1, 1–2 jornadas; fase 2, 2–3 jornadas; fase 3, 2–4 jornadas; fase 4, 1–2 jornadas. Depende de textos, criterios del docente, fotografías de prueba y decisiones de identidad. El mantenimiento inicial incluye migraciones, pruebas de permisos y revisión de adjuntos; WebSockets o IA solo se valorarían si existe una necesidad concreta y un beneficio demostrable.

## Microfases

1. **Escaparate y datos de ejemplo.** Resultado: cinco productos y ocho alias ficticios, consulta visual y navegación básica. Aceptación: datos repetibles, responsive y sin conversaciones expuestas.
2. **Encargos y asignación.** Resultado: creación/persistencia de consultas y figuras, adjuntos aún bajo controles, asignación manual docente. Aceptación: estados persistidos, destinatario opcional y pruebas de integridad.
3. **Identidad, permisos, panel y conversación.** Resultado: sesiones verificables, panel individual y mensajes privados. Aceptación: solicitante, alumno y docente ven solo lo autorizado; alias del navegador no concede acceso.
4. **Revisión visual y funcional.** Resultado: demo pulida y recorrido probado. Aceptación: móvil/escritorio, textos claros, accesibilidad básica, privacidad de fotos y regresión automatizada.

## Comparación breve

Webnode puede servir para publicar rápidamente un catálogo sencillo, con menos código propio. Taller Abierto aporta un modelo específico de encargos, asignación y conversación, control de reglas y una base extensible; a cambio requiere mantenimiento técnico, pruebas y decisiones de privacidad. No se presupone precio ni alojamiento: deben comprobarse cuando se evalúe una alternativa real.
